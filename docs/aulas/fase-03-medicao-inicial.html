2. Como servir o site para medir

Com o Next.js, a dúvida era “dev ou produção”. Com um site estático, a pergunta é: de onde o navegador vai buscar os arquivos?

❌ file://

Abrir o index.html com dois cliques. Não há servidor HTTP: nada de cabeçalhos, compressão ou cache reais. O resultado não representa um site de verdade.

❌ Live Server

A extensão do VS Code injeta um script de recarga automática e abre um WebSocket. Você estaria medindo JavaScript que o site não tem.

✅ npx serve .

Servidor HTTP estático de verdade, com compressão gzip ligada por padrão. Reproduzível e local. É o nosso padrão.

➕ GitHub Pages

Rede real, HTTPS e compressão. Permite rodar o PageSpeed Insights. Ótimo como bônus, mas a rede varia mais, então não misture com as medições locais.
terminal, na raiz do projeto
$ npx serve .
# Serving!  Local: http://localhost:3000   (deixe este terminal aberto)

Na primeira vez, o npx pergunta se pode baixar o pacote serve; responda y. Se a porta 3000 estiver ocupada, ele usa outra. Use a URL que ele mostrar, e sempre a mesma no antes e no depois.

O insight mais importante de hoje: LCP breakdown

Ele mostra qual elemento é o LCP (lembra do desafio da aula 1?) e divide o tempo em quatro fases. Quando o LCP é uma imagem, as quatro fases importam:

TTFB
load
delay
load duration

TTFBTempo até o primeiro byte do HTML. Num servidor local, quase zero.
Load delayDo HTML até o navegador começar a baixar a imagem. Cresce quando ela é descoberta tarde ou recebe prioridade baixa.
Load durationO download em si. Cresce com o tamanho do arquivo e com a disputa de banda com outras imagens.
Render delayDa imagem baixada até ela aparecer na tela.
Proporções ilustrativas. Minha aposta: no Pet&Style, o load duration vai dominar (160 KB numa 4G simulada, disputando com mais ~290 KB de produtos). Confira e anote.

6. Aba Network: peso e requisições

O Lighthouse dá tempos; a Network dá bytes, e é aqui que a otimização de imagens vai aparecer com mais força.

  1. DevTools → Network → marque Disable cache.
  2. Recarregue a página (Ctrl+Shift+R).
  3. Leia a barra de status, no rodapé.
  4. Clique no filtro Img e anote cada imagem.
  5. Clique com o botão direito no cabeçalho da tabela e ative a coluna Priority. Na fase 5, vamos mudar a prioridade do hero.

Valores que calculei a partir dos arquivos. O serve comprime texto (HTML, CSS) com gzip, que encolhe muito. JPG já é comprimido e não encolhe nada. Por isso, para imagem, a única saída é um arquivo menor de verdade: menos pixels e um formato melhor. Para conferir a compressão, clique no output.css → Headers → content-encoding: gzip.
