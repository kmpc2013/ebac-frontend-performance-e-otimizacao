1. Por que isso importa

O usuário não mede a performance em milissegundos, mede em sensações. Ele faz três perguntas, sempre nesta ordem, e cada métrica do Lighthouse responde a uma delas:

flowchart LR
  U(["👤 Usuário"]) --> Q1["① Está acontecendo
alguma coisa?"]
  U --> Q2["② Já dá para usar?"]
  U --> Q3["③ Está respondendo?
Está estável?"]
  Q1 --> FCP["FCP"]
  Q1 --> SI["Speed Index"]
  Q2 --> LCP["LCP ⭐"]
  Q3 --> TBT["TBT (≈ INP ⭐)"]
  Q3 --> CLS["CLS ⭐"]
⭐ = Core Web Vital, as métricas que o Google usa no ranking de busca.
Performance é requisito de negócio: a taxa de abandono sobe muito à medida que o carregamento passa de 1 s para 3 s, e as Core Web Vitals afetam a posição no Google. Página lenta perde usuário, conversão e busca orgânica.

3. As cinco métricas

FCP: First Contentful Paint

peso 10%
“Está acontecendo alguma coisa?”

É o momento em que o primeiro texto ou imagem aparece na tela. Fundo colorido não conta.

bom < 1,8 s1,8–3,0 sruim > 3,0 s

O que piora: CSS e JS no <head> bloqueando a renderização, servidor lento (TTFB alto), fonte segurando o texto invisível.

LCP: Largest Contentful Paint ⭐

peso 25%
“Já dá para usar?”

É o momento em que o maior elemento visível da primeira tela termina de renderizar (imagem hero, banner ou título grande). Analogia: o FCP é o garçom trazer o pão; o LCP é o prato principal chegar.

bom < 2,5 s2,5–4,0 sruim > 4,0 s

O que piora: imagem principal pesada ou com loading="lazy", fonte web lenta, renderização bloqueada.

TBT: Total Blocking Time (substituto do INP ⭐)

peso 30%
“Está respondendo?”

O navegador tem uma única thread principal para rodar JS, calcular layout e pintar. Toda tarefa que passa de 50 ms trava a página, e o que passa desse limite é o tempo de bloqueio. O TBT soma esses excessos entre o FCP e o momento em que a página fica interativa.

A Core Web Vital oficial é o INP (Interaction to Next Paint), que mede a resposta a cliques reais. O Lighthouse não clica em nada, então usa o TBT como substituto em laboratório: menos tarefas longas = resposta mais rápida aos cliques.

CLS: Cumulative Layout Shift ⭐

peso 25%
“A página para quieta?”

Mede o quanto o layout “pula” sem ação do usuário. É uma pontuação sem unidade (não são segundos). Experimente:

O que piora: imagens sem width/height, troca de fonte que muda o tamanho do texto, conteúdo injetado acima do que já está visível.

Speed Index

peso 10%
“Com que rapidez a tela foi sendo preenchida?”

O Lighthouse grava o carregamento (como a faixa de quadros da seção 2) e mede com que rapidez o conteúdo visual aparece. Duas páginas podem ter o mesmo LCP, mas a que mostra conteúdo aos poucos tem Speed Index melhor que a que fica em branco e aparece de uma vez.

bom < 3,4 s3,4–5,8 sruim > 5,8 s

4. Como o score de 0 a 100 é calculado

O score de Performance é uma média ponderada das cinco métricas:

TBT
30%
LCP
25%
CLS
25%
FCP
10%
SI
10%
Lição prática: TBT, LCP e CLS valem 80% da nota. Se o tempo é curto, ataque esses três primeiro. Ganhar 200 ms no FCP quase não muda o score.

Na atividade usamos dados de laboratório, e por isso:

  • as condições têm que ser idênticas entre o “antes” e o “depois” (build de produção, aba anônima, Mobile);
  • rodamos 3 vezes e usamos a mediana, porque o resultado oscila de 5 a 10 pontos entre execuções;
  • a nota Mobile sai pior que a Desktop de propósito, por causa do throttling.

7. Aplicando ao nosso projeto

Um profissional experiente prevê antes de medir. Depois compara a previsão com o relatório; é assim que se treina o olho. Estas são as nossas hipóteses para o Retro Tech Digest:

  style PERF fill:#f2b93b,color:#000,stroke:#f2b93b
  • LCP da home: sem imagens, deve ser um bloco de texto, o título “Home” ou o primeiro card. Texto depende de fonte, então as fontes de app/layout.tsx influenciam o LCP.
  • TBT: deve ser baixo, porque as páginas são Server Components estáticas e mandam pouco JS ao navegador.
  • CLS: pode vir da troca de fontes. O next/font já reduz isso com uma fonte reserva ajustada de tamanho, mas vale verificar.
  • body::after é custo de pintura e composição, que não entra direto no score. Só a aba Performance mostra esse custo, e é por isso que o enunciado cita as duas ferramentas.
