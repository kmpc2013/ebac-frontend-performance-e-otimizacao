Que tal praticar?

Performance não é luxo, é requisito de negócio: sites lentos perdem usuários, conversão e posição no Google. Este exercício coloca você no papel que qualquer front-end sênior assume regularmente — medir, diagnosticar e otimizar. Você vai pegar um projeto real (seu, do curso ou pessoal), medir sua performance com o Chrome DevTools (Lighthouse/Performance), identificar gargalos concretos e aplicar técnicas de otimização amplamente usadas no mercado, como compressão de imagens, lazy loading e minificação. No final, você vai comprovar a melhoria com números, não com impressões.

O que você vai desenvolver com esse exercício

  • Diagnóstico de performance com Chrome DevTools (Lighthouse/Performance) e, opcionalmente, PageSpeed Insights
  • Aplicação de técnicas de otimização de imagens, código e recursos
  • Comparação objetiva de métricas antes e depois das melhorias
  • Documentação técnica dos resultados obtidos

O contexto do desafio

Você vai escolher um projeto já desenvolvido durante o curso (ou um projeto pessoal) e submetê-lo a um processo de análise e otimização de performance. Primeiro, você gera um relatório inicial (Lighthouse ou aba Performance), documentando a pontuação e os gargalos encontrados. Depois, aplica um conjunto de otimizações obrigatórias e gera um novo relatório para comparar os resultados.

O que deve ser entregue

  • Repositório público no GitHub com o código-fonte do projeto otimizado
  • Dois relatórios (antes e depois), em PDF ou imagens
  • README.md documentando descrição do projeto, gargalos identificados, melhorias aplicadas e comparativo antes/depois

Passo a passo

  1. Escolha um projeto (do curso ou pessoal) para servir de base para a análise.
  2. Gere um relatório inicial com o Lighthouse ou a aba Performance do Chrome DevTools, registrando prints das pontuações.
  3. Liste os gargalos encontrados (imagens pesadas, requisições desnecessárias, JavaScript bloqueando renderização, etc.).
  4. Otimize as imagens: converta para .webp ou .avif, redimensione e aplique loading="lazy" onde necessário.
  5. Aplique minificação em HTML, CSS e JS.
  6. Remova código não utilizado (imports, funções e estilos mortos).
  7. Substitua bibliotecas pesadas por versões mais enxutas, quando aplicável.
  8. Gere um novo relatório de performance após as otimizações.
  9. Compare os dois relatórios e identifique quais mudanças trouxeram maior impacto.
  10. Documente tudo no README.md: descrição do projeto, gargalos, melhorias aplicadas e comparativo com prints.
  11. Suba o projeto para um repositório público no GitHub e compartilhe o link conforme as instruções da plataforma.

Requisitos obrigatórios

A avaliação considera a organização do projeto e da estrutura de pastas, a melhoria mensurável de performance entre o relatório inicial e o final, a aplicação efetiva de técnicas de otimização (compressão de imagem, lazy loading, minificação, entre outras) e a clareza do README na explicação das ações realizadas. Não é obrigatório atingir uma pontuação específica no Lighthouse — o que é avaliado é o progresso relevante e documentado, não um número absoluto.

Formato da entrega

  • Link de repositório público no GitHub
  • Relatórios "antes" e "depois" em PDF ou imagens
  • README.md com o comparativo documentado
